# Портативный комплект для inference с длинным контекстом (Strata + llama.cpp)

Одна сборка двух движков, которая сама смотрит на ваше железо и сама подбирает окно и
параметры. Все числа в ней — из замеров конкретного стенда (RTX 3060 Ti 8 ГБ, 4 ядра,
31.87 ГиБ ОЗУ, модели на SSD), а не из общих рассуждений; где замера нет, комплект говорит
об этом словами «это расчёт по формуле».

Моделей внутри архива нет. Комплект ничего не пишет вне своей папки.

## Быстрый старт

1. Распакуйте архив в любую папку (путь без кириллицы желателен, но не обязателен).
2. Дважды кликните `START.bat`.
3. На вопрос вставьте путь к файлу `.gguf` (можно перетащить файл на значок `START.bat`).

Комплект покажет четыре шага и попросит подтвердить запуск:

| шаг | что делает | файл |
|---|---|---|
| 1 | снимает железо: GPU, видеопамять, архитектуру, ядра, ОЗУ, тип диска под моделью, HAGS, MSI | `kit\detect.py` |
| 2 | сравнивает машину с нашей базой и говорит, что на ней не получится | `kit\classify.py` |
| 3 | по заголовку `.gguf` и классу железа считает максимальное окно и параметры | `kit\recommend.py` |
| 4 | запускает сервер и открывает адрес в браузере (флаг `-NoBrowser` не открывает) | `kit\start.ps1` |

Другие способы запуска:

```
START.bat model.gguf                     то же, но без вопроса о пути
START.bat model.gguf -DryRun             напечатать строку запуска и ничего не запускать
START.bat model.gguf -Yes                запустить без подтверждения
START.bat -FakeConfig 16g.json -Gguf model.gguf -DryRun
                                         подбор для чужого железа, не выключая своё
```

Полезно проверить комплект до первого реального запуска:

```
python kit\detect.py --selftest
python kit\classify.py --selftest
python kit\recommend.py --selftest
```

Нужен Python 3 (мы проверяли на 3.14); внешних зависимостей нет — только стандартная
библиотека. Если Python доступен как `py` — `py kit\detect.py --selftest`. Каждый из трёх
файлов умеет работать отдельно: `--out файл.json` записывает результат, `--json` печатает
машинный вывод.

## Что именно подбирается

Для Страты: размер окна, `--att-mb`, `--vram-reserve-mib`, super-chunk N, тип KV-кэша, MTP.
Для llama.cpp: окно, `--n-cpu-moe`, `-ub`, `-b`, `-fa`, число потоков. Порт Страты — 8082,
llama — 8081.

Окно считается по слагаемым видеопамяти: KV-кэш (байт на токен берётся из заголовка `.gguf`)
плюс attention-буфер, плюс запас, плюс состояние линейных слоёв, плюс (для llama) веса на GPU
при данном `--n-cpu-moe`. Шаг лесенки (64k, 80k, 96k, 128k, 160k) проходит, если сумма влезает.

Контроль честности: на нашей базе формула обязана воспроизвести замеренную лесенку с точностью
до одной ступени — это один из контролей в `recommend.py --selftest`.

## Модель, для которой подобраны параметры

`kit\models.json` — шесть замеренных моделей. У каждой строки есть ссылка на скачивание
(`hf_url`), проверенная по HEAD-запросу и совпадению размера, и первичник замера
(`src` — файл и строка таблицы). Если ваша модель не из этого списка, комплект подберёт
параметры по формуле и прямо скажет: «модели нет в реестре замеренных».

## Как читать предупреждения

Код возврата любого шага:

- `0` — verdict дан, замечаний нет;
- `1` — verdict дан с предупреждениями (текст напечатан; запуск возможен, но ожидайте
  медленного старта или меньшее окно);
- `2` — проверка не состоялась: битый вход, нет GPU, GGUF без метаданных. Это не «всё хорошо»,
  а «мерить было нечем».

Классы машины (`classify.py`) — по сравнению с нашей базой:

| вердикт | что значит |
|---|---|
| мощнее нашей базы | запас ≥ 1.5× по памяти; можно пробовать окно выше замеренного |
| не ниже нашей базы | ±5 %; все профили переносимы один в один |
| ниже нашей базы | что-то одно заметно меньше; часть окон не влезет |
| сильно ниже нашей базы | комплект предупреждает и перечисляет, чего не будет |

Тексты предупреждений и их смысл:

- «длинные окна (128k+) и MoE с CPU-экспертами в такую память не влезают» — упирается в видеопамять;
- «часть экспертов останется на диске, старт модели и прогон окна замедлятся» — мало ОЗУ;
- «CPU-эксперты (--n-cpu-moe) станут узким местом» — мало ядер;
- «загрузка модели с HDD измерялась только как ухудшение, не как профиль» — модель на HDD:
  наши профили снимались с SSD, время старта будет другим;
- «готового cubin для этой архитектуры в комплекте нет» — вашей архитектуры видеокарты нет среди
  собранных; расчёт идёт через PTX-JIT (медленный старт, непроверенный результат). Этот список
  берётся не из константы, а из `elf-proof.json` рядом с `kit\` — из доказательства по факту сборки.

## Какие конфигурации поддержаны

- Windows 10/11 x64, PowerShell 5.1 (оболочка комплекта — системная, pwsh 7 не нужен);
- видеокарты NVIDIA с архитектурой `sm_86`, `sm_89` либо `sm_120` — это Ampere (3060 Ti и
  родственники), Ada (4090, 4060 Ti 16G) и Blackwell (5080, 5090). Точный список собранных
  архитектур — в `elf-proof.json`, он же основание для предупреждения выше;
- драйвер, способный запустить CUDA 13 runtime (поставлен вместе с комплектом: `cublas64_13.dll`,
  `cublasLt64_13.dll`);
- модель в формате GGUF, помещающаяся в ОЗУ вместе с KV-кэшем подобранного окна.

## Вес

Полная версия (с CUDA-рантаймом) и тонкая (`-NoCudaRuntime`, cublas не едет) различаются
примерно на 488 МиБ — это `cublas64_13.dll` плюс `cublasLt64_13.dll`. Фактические замеры папки и
архива — в `kit-weight.json` рядом с этим файлом; он создаётся упаковщиком при каждой сборке
архива, поэтому число в нём всегда соответствует этому архиву.

## Как собрать комплект самому

Нужны pwsh 7, CMake, Ninja, MSVC и набор CUDA 13.3. Из корня стенда:

```
pwsh -File harness\scripts\build_kit.ps1 -Engines strata,llama -Arch "86;89;120"
pwsh -File harness\scripts\pack_kit.ps1                      # полная версия
pwsh -File harness\scripts\pack_kit.ps1 -NoCudaRuntime       # тонкая
```

Точка с запятой в списке архитектур обязательна в кавычках: без них оболочка разрезает аргумент.

`build_kit.ps1` пишет три меры в `dist\gpu-infer-kit`: `build-measure.json` (время и код возврата
настройки и сборки по каждому движку), `elf-proof.json` (какие cubin действительно лежат внутри
бинарников — снимается через `cuobjdump --list-elf`) и `runtime-deps.json` (замыкание зависимостей
через `dumpbin /imports`). `pack_kit.ps1` перед тем, как назвать архив готовым, проверяет: что все
обязательные файлы на месте, что в текстовых файлах дерева нет путей чужой машины, что меры
читаются как JSON без BOM, что собранные архитектуры покрывают заявленные, что зависимости
замкнуты, что архив открывается и что внутри нет моделей. Каждый контроль падает с внятной
причиной; отсутствие контроля — тоже провал, а не успех.

`-SelfTest` у обоих скриптов прогоняет контроли без сборки и без железа.

## Чего здесь нет

- моделей (архив не содержит ни одного `.gguf`);
- Linux и macOS;
- замеров на железе, отличном от нашей базы: предупреждение класса «ниже/сильно ниже» — это
  честная граница переносимости профилей, а не обещание тех же скоростей;
- MTP на окнах 64k и выше (измерено как ухудшение — в комплект не включён), и вообще всех
  отклонённых рычагов: их список с числами — в отчёте стенда `docs\reports`.
